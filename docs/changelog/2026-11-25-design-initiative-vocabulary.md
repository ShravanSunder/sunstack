# 2026-11-25: Design skills name initiatives, numbered projects and deliverables

- `sunstack-dev` 3.8.1 and `sunstack-workflow-v2` 0.7.1; all plugin and marketplace version entries agree for each. Follows the Demistify release that renames the typed design plan's levels; merge after it.
- The typed design plan's levels follow the library: an initiative (the whole plan, `initiative.ts`) holds projects (one design folder each, `docs/initiatives/<initiative>/projects/<project>/`, formerly a milestone), and each project holds deliverables. "Milestone" is no longer a level of the typed plan.
- Commands: `demistify initiative check` for an initiative (was `project check`), `demistify design check` for a standalone project. An agent's alias comes from the initiative's identity file.
- `design-documents.md` teaches the order: each project has a number, the owner's order (every project numbered 1 runs side by side, 2 comes after, then 3); dependencies run only between deliverables, in any project, and the initiative check warns when a deliverable depends on one in a higher-numbered project. `canonical-implementation-plan.md` points a design-bearing plan's dependency edges at that rule.
- Renamed mentions in `design-documents.md`, `diagram-rendering-and-fallbacks.md`, `canonical-implementation-plan.md`, `presentation-html` (skill, `demistify.md`, `engineering-documents.md`), `discuss-pathfinding`'s requirements extraction, `design-specification`, `design-program`, `design-verification`, `design-review` (skill, four-document reference, navigation lane, design-pages rule comment) and both plugin READMEs. Linear milestones and projects, the job-sizing ladder in `practices-delegation` and `practices-manage-agents`, and generic uses ("when a slice, milestone or PR ends", a repository's project root) are unchanged.
