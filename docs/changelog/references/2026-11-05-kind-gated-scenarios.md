## Evidence and admission

The 78 kind definitions preserve the experiment's source pin and partitions: 73 carried blind agreements, three owner rulings and two disputed labels. The 15 historical held-back identities are seen regression examples, not fresh holdout evidence. Disputed security/scaffolding labels are observed but unscored. Exact-kind errors and wrong gate decisions have separate counts.

A full gated run acquires every expected kind folder through the real engine with the canonical question, policy, model and evidence recipe. Missing, duplicate, extra, incomplete or cut filter evidence cannot earn adoption. Valid unsure is an explicit skip, neither right nor wrong, and does not itself prevent adoption; every rule scenario must still be caught with none unsure. Adoption rechecks current populations, labels, derived scores and canonical config/corpus identities. Changes to the kind corpus, filter question/bar/projection or accepted gate set invalidate earlier evidence and hold prior adoption.

Kind-corpus runs keep the complete real standards/entry pair for native marker coverage, so sibling graphs can add requests. Usage/spend, downstream rule-piece cuts, rule-graph uncertainty and unresolved selections are retained and printed. In that isolated run, those downstream observations do not invalidate complete filter acquisition. A kind-corpus native exit 5 can therefore accompany a complete passing scenario report; it is not reported as a clean native engine run. Filter-input cuts, native errors, assembly/config/coverage gaps and engine exits other than 0/5 remain blocking. Rule-scenario runs block semantic cuts, uncertainty and unresolved selections at declared (rule, file, piece) identities; undeclared pieces, including the requested rule's other pieces, remain visible as supplemental evidence. Native incomplete responses and assembly/config/coverage errors remain globally strict. Ordinary lint is unchanged.
