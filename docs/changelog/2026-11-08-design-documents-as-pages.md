# Design documents are pages on the released document browsers

- sunstack-dev **2.108.0**: a design set is one folder of HTML pages built on Demistify 1.21.0's requirement and call-stack browsers: a home page, `requirements.html`, `specification.html`, `program-design.html`, `verification.html`, a call-path page (`execution.html`), deliverable pages when the work has deliverables, and plan pages in `plans/`. No Markdown file holds a design, and there is no `index.md`; agents and the owner read the same pages.
- Each document's text lives in sections and record bodies at stable IDs. Each record names only what it serves (a need its capability, an obligation its needs, a design part or check its obligations, a call stack its need and frames), and preparation and the browsers derive every reverse link. A check written at design time carries no result.
- `shared-references/design-documents.md` and `diagram-rendering-and-fallbacks.md` carry the new model, preparation and freshness; `orchestrator-design` gains the deliverable stage (delivery cut, first deliverable page, scoped plan).
- Phases write their own pages: `spec-design`, `discuss-pathfinding` (the confirmed capability list and the durable record go onto the Requirements page), `program-design`, `verification-design`. `presentation-html` composes design pages from the released guide; `spec-program-review` checks a page set by phase state and walks capabilities through derived links; `docs-maintain` edits the owning section or record body and prepares the set again.
- `plan-implementation` and `canonical-implementation-plan.md`: a plan from a design set is a page, optionally scoped to one deliverable's needs and their proof; other plan homes stay Markdown.
- Known limits: the Specification's whole-set capability map waits for a Demistify view the owner chose; until it ships, `spec-design` names that composition gap in its return and keeps going. The skills copy the CLI URL that Demistify's main guide prints, which is content-addressed since Demistify 1.21.1.
- Existing Markdown design sets stay readable where they are; nothing is migrated.
