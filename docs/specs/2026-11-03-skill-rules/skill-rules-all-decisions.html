How it will work once switched on (designed, still being tested)

What Jev reads (a separate model call, not the agent's context)

  • Kind check: only the skill's one-line description.
  • The rule: one section at a time, at most 50,000 characters, plus the first 3,000 characters of each file it loads. One request is at most 131,072 bytes, and a choice question has at most 255 options. If text is cut to fit, the result says so.

What the agent sees (its context)

For a warning, today's printout is short, about 6 to 8 lines, with no pasted skill text. Illustration only (the rule is switched off, so no real warning exists yet; the numbers are made up):

       step, branch or load into one product's own application workflow …
  Answers: {routes_product: yes 0.85, shared_only: no 0.20}
  read: target references/agentstudio-loop.md   (a file this section loads)
  same rule also nudged: …

Two things can still flood the agent's context today; number 7 below proposes limits for both:

  • For each unsure section, the printout pastes the whole section as evidence, up to about 50,000 characters.
  • Nothing limits how many warnings one run prints.

What must pass before it can be switched on

  • Thresholds (how sure Jev must be): warn only on a clear yes to question a and a clear no to question b; anything in between is listed as unsure, not warned.
  • Must-stay-quiet tests: real text such as pnpx shadcn add button, a metrics query and cargo clean. If any of them warns, the design is rejected.
  • All the labelled test passages must pass, then 6 more, kept from whoever tunes the rule, are run once. (This is the current rule; question 8 below would change it.)
  • You switch the rule on. If its questions, thresholds, test passages or the kind check change later, it switches off until it passes again and you switch it on again.
