Why this split

ThingWhereBecause
Rules, config, ast-grep, standardsskill folderthey run, and they ship with the skill
Scenariostests/skills/evals/rule-scenarios/test data; your rule and AGENTS.md ("tests and evals belong under tests/")
One file per rulenamed after the ruleopen the rule's name, find its scenarios; adding a rule adds one file
Run resultstests/skills/tmp/, ignoredgenerated, and they go stale on any edit; your rule: never in git

1. If run results aren't in git, how is a passing run tracked?

This matters because of how agents use the rules. An agent runs the lint without the Jev key, so it can't rerun scenarios. Today it learns "this rule passed its scenarios" from the saved result file. Without that file in git, something else has to say it, or every judged rule stays hidden for agents.

2. How are scenarios run?

Names that change everywhere

"case" becomes "scenario" in files, code, designs and pages: *.cases.json → *.scenario.json, "case run" → "scenario run", cases.ts → scenarios.ts. The run-result file *.case-run.json goes away; its job moves to your answer to question 1.
