## Evidence

- API-key case: `/private/tmp/2026-10-agent-readiness-cleanup/sunstack-tools-api-key-block.md`. The Lead knew the key was missing and decided "This only matters at the hosted-proof step, so the work can start without it", while the plan's milestone gate required hosted tests (V29/V30). The start was actually blocked by something else: the Lead couldn't create the four Sol sessions the plan assigned. No skill told it to check what every required gate needs, or whether the agents the plan names can be started, before commissioning.
- Disk: `/private/tmp/2026-10-agent-readiness-cleanup/cleanup-allowlist-report.md`. Measured now: Rust `target/` 156 GiB (largest 118 GiB), Swift build output 30 GiB, repo `tmp/` 28 GiB, node_modules 21 GiB, 13 integrated worktrees still on disk (8 at their exact merged PR head). Incidents: linker and shell ENOSPC, the volume at 0 bytes free, 54 GiB left in a merged worktree, and rebuild churn from cleaning after every proof.
- Today's skills: `implementation-pr-wrapup/references/local-branch-state.md` says "Preserve worktrees after PR creation/update. Do not run destructive cleanup unless the user explicitly requested it." Wrap-up stops at PR-ready, and the owner merges, so no agent is present after a merge. The global rules forbid `rm` on directories and worktree removal without asking.

## Success

- An agent that starts an orchestration, a plan's implementation, or a commission first lists what success needs: inputs, access, credentials by name, services, tools, the agents the plan assigns, and disk headroom. It checks each one for real, and closes or raises each gap before dependent work starts. A credential that a required gate needs is a start prerequisite, not "later".
- An agent removes what its own task created once nothing needs it: bulky build output at milestone or PR boundaries, or when the disk is low; large logs once their evidence is kept; its task temp folders; and its merged worktree with the untracked files it doesn't need. It does this without asking, inside the allow list, and asks for anything outside it.
- A language skill loads when a caller names it, teaches the owner's standards for that language, and cites principles at the decisions they inform. The Implementer walks its changed code against it before handback, and the reviewer checks against it.

## Boundaries

- Layer rule: practices name practices, principles and domain skills. Phases reach the new practices only through their own calls. Domain skills name only principles.
- The owner's safety rules stay in force for everything outside the allow list. No cleanup of shared caches, other agents' work, or anything whose owner or consumer is unknown.
- No pressure tests. Proof is static checks plus an adversarial Sol review per skill, with Opus Workers writing through skill-creation and a slop and infractions inventory.
- Not pedantic: each skill teaches the judgment with a worked example and keeps lists only where agents copy them.
