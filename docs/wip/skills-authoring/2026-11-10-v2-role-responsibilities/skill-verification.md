# Verification and review plan

## What the evidence may establish

The basis is user-directed intent. Design review can establish that the proposed text and ownership are coherent; source review and lint can establish inspected source properties. Neither proves agent compliance, causal token savings or reliable multi-day delivery. No paid/fresh agent behavior evaluation is commissioned by this plan.

## Design walkthroughs to inspect

- Implementer chooses internal functions/test order without a Lead microtask; moving retry ownership across a contract returns to Lead.
- Verifier repairs its granted driver and sends a real product defect to Implementer; neither edits the other's files or changes the expected outcome by agreement.
- Operator follows a prescribed retry and returns an unprescribed auth failure to its actual commissioner.
- Lead reads an unsupported integration claim despite green component tests and leaves readiness open; a deferred prerequisite remains unresolved on resume.
- Checker finds an original owner constraint omitted from the Lead's accepted candidate; the finding reopens affected acceptance and proof, which the Lead checks before the corrected candidate returns for affected review.
- Lead's assessment cites a current component test for an unobserved user journey: Checker compares it to the original requirement and rejects the inference; Lead obtains missing evidence instead of delegating authorship of its assessment.
- Startup opens the assessment along with governing sources, or the shared record exposes it: Checker still derives its criteria from the originals and audits the claim; no blind-review claim is made. If only the assessment is available and original decisions are missing, report an input gap instead of approving within the Lead's framing.
- A review repair changes the observed target: affected proof and review coverage are refreshed; unrelated valid evidence is reused.
