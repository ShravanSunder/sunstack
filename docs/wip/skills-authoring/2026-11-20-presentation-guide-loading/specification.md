## Specification

- **R1.** Assign the reader's question and required information to the design phase, the component choice to the presentation skill, and exact syntax to the Demistify guide for the bound runtime.
- **R2.** Load the shell and checking instructions once per binding, then load only the component references required by the selected views.
- **R3.** Use verified local Markdown when its release matches the page's binding. For an unmatched release, use the guide for that binding.
- **R4.** Keep the page's explanation in hand-authored HTML, with exact stable destinations for evidence and navigation. An optional typed record may derive JSON used by Pages, Map and Walkthroughs.
- **R5.** Make a guide refresh reviewable from its release identity and the changed reference files.

For a schema change, a small table may answer the owner's choice and only the shared navigation reference is needed if the document spans pages. For a persistence change, a diagram may explain ownership and a Walkthrough may link the state transition to planned proof. That author also opens the Walkthrough reference. Both cases follow the same authority chain and keep factual prose at the authored destination.
