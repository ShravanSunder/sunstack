## Specification

The design phases own the planned record and the stable links between needs, rules, realizations, decisions, assumptions and checks. The plan names the scoped IDs and the browser and CLI binding. The delivery Verifier owns its later observation. The Lead owns acceptance of the candidate and current scope. An assigned builder can differ from the milestone Lead.

Presentation chooses a view by reader question. When the reader is asked to answer, use Choice and offer Details if extra depth helps. When the reader needs to understand consequences, use a comparison. For a settled answer, use the existing decision presentation and link to its source. Pages provide destinations, Map groups related topics, and Walkthrough sequences an explanation. A milestone delivery view shows its own work. A project overview shows owner questions, milestone links, and cross-milestone waits.

The matched Demistify guide owns exact markup, schemas and command lines. It teaches declaring a site root, registering a reviewed page, citing its exact authored fragment, and checking without touching generated files. An authorized refresh prepares the current reader data. The author chooses commands and components supported by the actual binding.

### What to give an agent

Give the agent the project and milestone roots, the authorized site root, the matching Demistify binding, the existing reviewed pages, and the reader's question. Ask it to write the explanation directly in HTML and keep the record IDs, links and delivery state in the typed files. It should use the checked destinations for an existing Map or Walkthrough, check the project before refreshing generated data, and return the actual reader link and check result. Before handing over a direct-file reader with Markdown includes, embed the authored Markdown through the matching CLI.
