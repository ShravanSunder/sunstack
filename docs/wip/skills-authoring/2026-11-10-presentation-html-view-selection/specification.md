# Observable obligations

- R1: Content representation follows the reader's task and source structure, with no default preference for prose or first-match ordering that hides other needs.
- R2: A short opening answer does not satisfy a separate need to see flow, ownership, comparison, states, branches or evidence.
- R3: Use the matching component guide for syntax, while the HTML skill owns selecting and composing the explanation.
- R4: Show only source-supported relationships, preserving unknowns and factual limits; a simple fact can remain prose.
- R5: Retain existing carried-form preservation, safe binding, navigation, optional depth and static-versus-rendered proof limits.
- R6: No diagram quota, fixed card template, D2-specific recipe, or newly required browser matrix.

Transfer checks: a database migration with ordered failure/recovery and an API ownership explanation both need structural views (R1/R2). A one-sentence configuration default and an explanation with unknown call order must not gain invented arrows (R4/R6). A comparison of two algorithms and a numeric trend use different suitable views (R1/R3). An existing supplied screenshot and a carried diagram retain their form rather than being replaced to satisfy the new chooser (R5). These cases test generality in both directions, not one project's preferred diagram.
