# What the revised teaching must accomplish

Revision: 1, correction 1 (material-cost coverage).

## Obligations

| ID | One obligation | Need |
| --- | --- | --- |
| O1 | Explain material agent-made decisions in the main account with the choice, reason and material cost or consequence, actor, covering authority or authority gap, and current state, naming missing rationale or cost evidence rather than inventing it. | U1 |
| O2 | Explain material relied-on assumptions in the main account with the belief, dependency, evidence so far and what remains to settle it. | U2 |
| O3 | Reconcile later corrections, withdrawals and settlements within the declared source scope before showing a decision or assumption as current. | U1, U2 |
| O4 | State a source-coverage gap when the inspected account cannot establish the material decisions or assumptions, rather than inferring an empty register. | U1, U2 |
| O5 | Teach how one account gives complementary jobs to an ordinary table, a meaningful progress part, a supported comparison, an evidence Trace and optional local detail. | U3, U4 |
| O6 | Apply the actual component reference at the selected binding before writing its syntax, preserving the guide as the API owner. | U3 |
| O7 | Keep an exact known progress fraction separate from status, approval, elapsed time and the strength of verification. | U4 |
| O8 | Judge source coverage and component meaning separately from the final static markup check. | U1–U4 |

Main account means visible explanation under the existing four headings; a material fact may appear once and be linked from other relevant sections. This is not a requirement for a second register, repeated fields under every paragraph, or another large card around every section. Optional receipts may remain disclosed; the important choice, uncertainty or limit stays visible.

## Standards and transfer tests

| ID | Judgment to teach | Different case where it holds | Bad choice it rejects | Verdict |
| --- | --- | --- | --- | --- |
| S1 | Identify who made a choice separately from the authority that permitted it. | A release lead selects a rehearsal order within an owner-approved rollout. | Calling a reviewer-approved retention period the owner's preference. | Pass: attribution and permission remain distinct in both cases. |
| S2 | Explain a relied-on belief with the work that depends on it and the evidence still missing. | A migration assumes spare disk space for its second copy. | Presenting a chosen timeout as measured network latency. | Pass: it applies beyond software layout and rejects a conflated measurement. |
| S3 | Preserve actual corrections and unresolved evidence limits when composing the current account. | A hardware report withdraws its initial battery diagnosis. | Reopening an answered capacity choice because its old answer widget remains. | Pass: chronology does not substitute for a settlement. |
| S4 | Choose a structured view for the relationship it makes easier to inspect. | A research comparison aligns the same questions across several studies. | A dependency tree that implies chronological execution. | Pass: the relationship selects the form across domains. |
| S5 | Use progress counts only when their numerator and denominator describe the same known subject, while preserving any explicitly requested valid visual. | Four of six prepared samples passed an assay; release approval is separate. | Turning three differently sized test suites into an overall delivery percentage. | Pass: counting and outcome remain distinct. |
| S6 | Give each material claim the decisive supplied evidence beside it and keep full receipts as optional depth. | An incident account quotes the failed health observation beside its finding. | A trace labelled verified whose sole attachment is an entire archive link. | Pass: evidence supports the particular claim rather than its surrounding project. |
| S7 | Use native HTML structure for live components and the documented source carriers for literal technical material. | A scheduling table contains a supported status component. | A Markdown table displays escaped component tags as if they were active badges. | Pass: a rendering boundary is chosen from content, not a project-specific tag blacklist. |

The example must also show when to omit a view: unknown totals cannot produce a progress fraction; unrelated facts need no forced comparison; a single observation needs no manufactured sequence. Components are alternatives with jobs, not a quota.

Source reconciliation stays read-only. A missing authority is a visible gap, not permission for the page author to retrospectively approve the decision or invent a source event.
