Work-log view skill change

presentation-show-worklog will build the owner's approved work-log view. A dated page has four question sections in a fixed order, one h4 item per topic, and a view for each topic only when its evidence earns one: a consequence badge, a Flow, or before and after cards. Verification is one table with the shared data-layout="verification" marker. Every detail link reaches a full account: either the existing stable one at the same cutoff, or a companion that carries every source row unabridged. A topic with no evidence for a view is still explained, in plain prose, under its section.

Two runs, both proposed. Run 1 rewrites the skill's step 3, drops the decision-brief branch from step 2, and adds two references: section-views.md and full-account.md. Run 2 adds one caller-generic sentence to presentation-html's work-account-forms.md, and the same clause to patterns.md: a calling skill's page contract decides the forms for its page. Neither run changes a trigger.

The Lead's 27 Nov rulings closed all three questions. D14: the pointer goes in both references. D15: this skill owns the work-log view recipe. D16: the second proof input, rows-2026-11-26.jsonl, exercises the companion. The design review has not run yet.

Terms: the view is the compact work-log page; the full account is the page its detail links reach; the companion is a full account this skill produces when no stable one exists; an item's face is its title, optional badge row, outcome sentence and detail links.
