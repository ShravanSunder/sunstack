Work-log view skill change

presentation-show-worklog will build the owner's approved work-log view. A dated page has four question sections in a fixed order, one h4 item per topic, and a view for each topic only when its evidence earns one: a consequence badge, a Flow, or before and after cards. Verification is one table with the shared data-layout="verification" marker. Every backing-evidence link reaches a full account: the existing stable one at the same cutoff (a supplied dated report counts), or a companion written only when none exists, carrying every row in the declared snapshot unabridged. A topic with no evidence for a view is still explained, in plain prose, under its section.

Two runs, both implemented. Run 1 reorders the skill: step 2 reads the source and settles destinations without writing anything; step 3 assigns sections, binds, writes the companion if one is needed, then writes the view. It drops the decision-brief branch, adds two references (section-views.md and full-account.md), and teaches read-and-summarize.md report intake. Run 2 puts one precedence rule in presentation-html/SKILL.md:10, with a scoping phrase in work-account-forms.md:3: a calling skill's page contract decides the forms it names. Neither run changes a trigger.

Design review round 1 returned targeted-revision with 13 corrections. The review lead verified them at 51053f19 and closed the review as accepted-to-implement. Both runs are written and implemented. Proof round 1 failed on wording; corrections F1–F7 are applied (D23), and a fresh proof round and the implementation review are still owed.

Terms: the view is the compact work-log page; the full account is the page its backing-evidence links reach; the companion is a full account this skill produces when no stable one exists; the page contract is the section table, item face and section views this skill hands presentation-html; an item's face is its title, optional badge row, outcome sentence and links.
