## Common craft and schema ownership

Each skill opens with the engineering question and mental model, gives a short usable main path, and calls depth at the decision that needs it. The body carries the choice and completion boundary; the reference carries worked variations and mechanics. Teach positive judgment and one concrete failure/clean case instead of adding an excuse table to every topic. Principles are read in full when named and applied; never duplicate their manuals or force the whole catalog into every phase.

Use existing collaboration/trace/research/management/presentation methods at their actual boundaries. Phase inputs are pointers to the governing artifacts plus enough context to locate the question; no copied document store, shared index, per-step checklist report or graph of administrative IDs. Stable existing requirement/rule references can show coverage, but a link proves location, not correctness. Natural-language design documents remain natural language; no Markdown parser or AST-linter project.

Place shared document identity/home definitions in the existing shared design-document owner, updated to five responsibilities. Phase-specific instructions and result schemas live with their owning skill. A genuinely shared phase-return union may compose separately defined variants; role-specific/domain fields are never duplicated. A role or phase needing one return opens that owner's schema, not the whole family's source. The cycle/review outputs reference artifacts and report real gaps; schema validity cannot prove authority, confirmations, complete reading or correctness.

Preserve strict typed boundary validation, readonly values, named discriminants and required payloads with `z.infer`. Do not cargo-cult #122's schemas: its `headCommit` age-only wording conflicts with current applicability guidance, and five array items do not establish five distinct document responsibilities. The selected design must establish the actual five-document set and evidence coverage, with a fitting real consumer/test; do not manufacture another schema framework to encode every prose judgment.

## Runs and their four surfaces

Every run names exactly one target. Consumer/schema/changelog edits only support that target's changed contract. All rows begin proposed; implementation waits for accepted source spec and a Lead commission. Trigger intent is preserved or narrowed to the stated job; client discovery metadata follows the active plugin conventions.

### Run 1 — spec-design

Trigger: author/revise Requirements or observable Specification from settled meaning; unknown owner intent remains pathfinding, structure remains Program Design.

Main path: frame consumer problem and scope from current source; distinguish adopted needs from proposals; define the domain identity/state/invariants; express observable normal and failure obligations; challenge material wording with the cheapest implementation that satisfies its words while missing the intended outcome. Bring only the meaning the sources cannot settle to the owner. Preserve the adopted Requirements confirmation and separate Specification home.

Depth: problem/provenance and adoption; domain/observable-rule reasoning; revision against the confirmed baseline; views selected by the reader's question. Calls name the required result and exact load condition. Read shared-model/scope/domain/ground-truth/tradeoff principles at their decisions, and reader clarity at hand-on.

Proof: static source walks for intended-pane arrival versus acknowledgement/wrong-pane, a legitimately adopted constraint versus an invented restriction, and a revision preserving unaffected obligations. These are illustrative cases, not AgentStudio requirements. Fit existing source checks to retained obligations; no test that only matches whole paragraphs as teaching proof.

### Run 2 — program-design

Trigger: structural How from governing meaning, or a concrete seam/observation gap; no redefinition of product nouns or test strategy.

Main path: trace current entry-to-effect and error/recovery paths; identify the crux; compare credible boundaries and name their cost/payer; choose ownership and states; walk a representative caller and a relevant failure/interleaving; place honest test seams and observation points. A typed binding table records the choice after reasoning. Preserve structure confirmation and source-backed visual requirements.

Depth: current system; crux/alternatives/falsifier; parts/types/contracts/call paths; conditional failure/concurrency/trust/performance; seams; view/rendering procedures. Use one-truth/types/separation/complexity/failure/concurrency principles conditionally, without turning every possible topic into a mandatory review lane.

Proof: source walks of one clear ownership design, competing retry/timeout owners and an in-flight callback after lifecycle closure. Show which claim is invariant, which is owner meaning, and which needs observation. Preserve explicit migration/cutover policy: an old stored value or deployed consumer does not justify an unapproved compatibility path.

### Run 3 — test-design

Trigger: regression scenario/oracle/layer design; implementation writes tests, verification proves delivery, Reviewer audits actual tests.

Main path: start with the specified wrong behavior; establish what must remain real for it to reach the assertion; choose the cheapest honest layer using determinism/diagnosis/runtime cost; derive an independent expected outcome; arrange a fixture that reaches the case; choose completion/timing controls; inspect existing protection. Each assertion accepts every permitted outcome and rejects forbidden ones, without requiring incidental order or wording.

Depth: layer placement and mocks as assumptions; existing-test keep/repair/remove with rationale; false-green/fixture/oracle/timing examples. Load tests-that-can-fail at scenario/oracle decisions. The pyramid is distribution, not a quota; integration keeps the interaction real, broader journeys prove the composition only they can observe.

Proof: source walks for serializer-only behavior, an actual routing interaction and visible rendering; correct implementations must finish and pass; wrong behavior must reach the intended assertion. No temporary tests, sleeps or mandatory condition-flip/mutation tool. Test Design plans RED, while the executor's actual run proves it; setup errors and invented chronology remain gaps.

### Run 4 — verification-design

Trigger: independent proof design, prebuild feasibility/adequacy challenge or delivered observations under the supplied grant; no general product fix or model-generated correctness oracle.

Main path: name the adopted core outcome/reference; inspect the existing driver and what target/config/boundary it actually exercises; choose cases against remaining risk; locate a real outcome observation; define passing and unverified limits; plan appropriate reuse. A planned test is not proof. At delivery the paired Verifier interprets actual current-target results and the Lead accepts.

Depth: reference/cases; real surface/readiness versus preparation; symptom-oriented before/after proof; prebuild challenge; delivered report. Use prove-it-works/verify-before-accepting and existing route methods. A second path earns its cost only when it detects something the first cannot. Driver work stays within #127's explicitly assigned apparatus paths; product tests/repairs stay Implementer-owned.

Proof: source walks for a real user outcome versus IPC acknowledgement, offline doctor versus live readiness, wrong binary/reference, and an adequate permanent journey reused at a later applicable source. Typed reports preserve observed target/reference/results/limits and truthful reuse; no current-head timestamp alone establishes applicability.

### Run 5 — spec-program-review

Trigger: independent review of one declared design target or the full five-document set before planning; skill quality remains skill-review and implemented code remains implementation-review.

Main path: admit targets/governing sources and author independence; reconstruct consumer intent; walk a concrete case/countercase through observable rules, ownership, tests and real proof; challenge risky assumptions against decisive sources; examine coverage and ungrounded extras; return smallest semantic findings/gaps to their owners. Corrected closure stays in the same review relationship. Reviewer does not edit or accept.

Depth: per-document engineering lenses; coverage links; proof claims; conditional named risks and reader/navigation; findings and convergence. Existing source review status/route rules retain their authority; no old disputed result-policy or risk-ledger additions. Preserve applicable visual checks and direct governing evidence reads. Cross-model staffing comes from management, not a copied phase catalog.

Proof: source scenarios include a fully connected but wrong requirement, a good design that needs no change, a mocked-away proof path, a correction without recurrence and a genuinely missing owner decision. Traceability alone never settles semantic correctness. No fresh runtime experiments commissioned by this skill change.

### Run 6 — orchestrator-design

Trigger: whole bounded five-document design cycle, with direct phase work staying direct and delivery remaining separately owned.

Main path: re-anchor current intent and sources; identify the unresolved decision and dependencies; load the smallest phase that can settle it in the Lead session; interpret its material result; route evidence of drift/break under existing global authority; continue through the independent review and retained corrections; show readable current decisions/limits for the final adopted confirmation. The dependency order remains real, while investigation can inform feasibility before a downstream document is finalized.

Depth: actual shared document responsibilities and owner decision brief; thin phase/cycle return contracts; correction/continuation mechanics. Use scope/shared-model/tradeoff/refine-models/verify-before-accepting where they change the next action. The controller must state what was assumed, what evidence showed and what it means for the design, not relay completion tokens.

Proof: static walks for an unchanged sound model, a wrong ownership assumption uncovered by test feasibility, an unresolved blocking decision, and evidence deliberately due at delivery. All five responsibilities and adopted confirmations remain; no automatic short path, extra approval gate, parallel authoring swarm or fabricated ready signal.
