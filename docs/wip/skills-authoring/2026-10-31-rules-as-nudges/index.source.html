Rules as nudges

A rule collects the piece of a skill its question needs, asks Jev about it, and gives the agent running it a nudge: what it saw, where, which standard makes it a concern, and where else to read. The agent reads those places and decides. "Nudge" is your word from 12 October; the engine has called it warn since the 18 October rename, and a warn never fails our runs, so nothing new is needed for it.

How a rule works

Each box is one step; the engine does the first four, the agent does the rest.

Blue is what we write, amber is what the engine does, teal is what the report says, violet is what the agent does. Besides the nudges, the run lists its gaps: files a rule was meant to read and didn't, pieces whose text was cut, and questions the engine couldn't settle.

Line 17: what happened, and what the design does

PR 187's AgentStudio line, ops-observability-stack/SKILL.md:17. Every step in "What happened in PR 187" answered a narrow question; nobody asked whether the line belonged in a generic skill.

The call-completeness rule wasn't wrong; it saw a real missing return. The failure was my commission turning its nudge into "make it pass", and no rule asking about placement. In the design both rules nudge on the same line and the agent puts them together.
