Design pages state the author's assumptions and decisions

The answer

Revision 3. Every assumption and decision on a design page becomes a marked item, an HTML aside carrying its kind, an id (A3, D4) and its authority: the owner's own words, agent wording the owner accepted, an existing contract, the author's own call, or unknown. The author writes the item in the same edit as the sentence it governs, so a missing authority shows while drafting, not at the end. Option text the owner picked is accepted agent wording, never the owner's words, and any wider reading of it is the author's own assumption.

Every check is a nudge, never a gate. The author's self-check, and then the reviewer, ask of each sentence that settles meaning whether its source supports all of it, give each item every applicable label from a shared set of ten, or ok alone, each saying what was seen and where else to read, and look quotes up by authority when an owner-message export is supplied. The author ranks its own-call items; the few high-value ones go to the owner as decisions, and the entry page lists every item in rank order. Existing decision-needed rules stay as they are; no blocker is added.

Four runs, one skill each: design-specification (which also writes the new section of the shared design-documents.md), design-program, design-verification, design-review. No description, rule, engine or Demistify change. Open: re-review of this revision. The owner decided no Demistify element (D-21, D-22). All owner quotes are exact spans of the refreshed export. Behavior is not yet evaluated.
