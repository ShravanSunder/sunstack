Principle loads: the change at a glance

A principle is a short guide that teaches one engineering judgment, such as "verify before accepting". Skills point to principles at the steps where that judgment matters; each such place is a call site. Today a call site is a link in brackets at the end of a sentence.

After this change, each call site says MUST load the principle at that moment and return what applying it produced. The intent is that the step can't be finished without reading the principle; whether agents actually do that is not yet tested. Runs that never reach the moment load nothing.

Why: the audit's session-log search flagged a possible principle read after its skill loaded in only 3 of 148 candidate cases on Claude and 632 of 2,883 on Codex; those are search hits, not confirmed reads. It misses some reads and can't tell whether the moment came up, so it's a weak signal, not proof that agents skip the links.

Waiting on you: how wide?

You asked for the v2 roles and base practices: 19 skills, 73 call sites (18 the audit looked at, plus plan-implementation, which was added to v2 after it). Once the skill-writing standard changes, 11 other sunstack-dev skills (domain-rust, domain-typescript, domain-python, domain-code-standards, the three presentation skills, debug-investigation, the two ops skills, audit-security-review) would break it, with 38 call sites between them.

Recommended, not chosen. Including them keeps one rule across the plugin, so no later review flags those 11 skills. It costs 11 more small runs in the same PR. If you'd rather not: say "drop D3", and the change stops at those 19 skills; the other 11 keep the old form until a later change.

The rule, in one picture

Each principle call keeps the moment it has today. The only question per call is whether every run of that step reaches the moment, or only some runs do.

Before and after, on real lines

Three lines from today's skills, one for each way a call gets rewritten. The principle is named the exact way the skill will name it: a relative path in base skills, a sunstack-dev: name in v2.

The moment is a condition, stated first (practices-research)

Before accepting a load-bearing conclusion (one the work depends on), name the anchor (the source you checked) you opened for it and what that anchor doesn't cover ([verify before accepting](…)).

Moment is a condition (practices-how)

When a term is overloaded, or the code and the docs use different words for what may be one thing, state what it refers to and what makes two of them the same before you explain with it ([define the domain first](…)).

The step itself is the moment (role-implementer)

Build a scenario that can fail for the required wrong behavior, exercise the real boundary and keep its assertion oracle and observed red, or name that no pre-fix red was seen (write tests that can fail (…)).

In plain words: write a test that would fail if the bug were there, exercise the real part of the system the test is meant to check, keep what it asserts, and show it failing before the fix (or say you couldn't).

The moment is a condition, stated first

IF you are about to accept a load-bearing conclusion, MUST load ../principle-verify-before-accepting/SKILL.md and return the anchor you opened for it and what that anchor doesn't cover.

Moment is a condition

IF a term is overloaded, or the code and the docs use different words for what may be one thing, MUST load ../principle-define-the-domain-first/SKILL.md and return what it refers to and what makes two of them the same, before you explain with it.

The step itself is the moment

MUST load sunstack-dev:principle-write-tests-that-can-fail before building the scenario and return a scenario that can fail for the required wrong behavior, exercised at the real boundary, with its oracle kept, and either its observed red or a note that none was seen.

What gets changed

A run is one skill's update. Runs 1 and 32 come first: the standard every skill is written against, and the review check that judges it. Then each citing skill gets one small run, in any order.

Run 1 replaces the rule "a principle is only cited, never loaded" with the load form above, and updates the glossary and the maintainer docs to match. Run 32 updates the skill-review check, so reviews judge principle calls by the new rule. Everything lands in one PR, with all three plugins' versions bumped and a changelog entry.

What stays the same

  • Which principle is called where: no call is moved, added or swapped.
  • The principles themselves. When one principle points at a sibling, that stays a plain link, so one read doesn't pull in a chain of others.
  • Your CLAUDE.md "before X, read principle Y" lines. That's a separate decision.
  • Frozen v1.
