## How run 1's engine check runs

ai-tools has no way to run the engine today: no script, CI job or package entry names it. So run 1's check uses the engine repository's own documented route, as a one-off proof, not as ai-tools' runner (that question waits for milestone 2).

- **Binary:** `sunstack exec` from `sunstack-tools` at `7403724`, built once in that checkout with `scripts/cargo-debug-signing-runner.sh` as its README says. It isn't built today, so preflight builds it and reuses that one build.
- **Fixture:** under the worktree's `tmp/project-1-u0-proof/`: the three marked lines and three entries from `markers-and-rules.md` as corrected, a RuleSet, and a `check_rules` request with `output: assembled_rules`, in the shape of the engine's `marked-standards.check.request.json`. A second request differs only in the uncorrected `"severity": "block"`.
- **Kept:** both requests and both responses, with the exit codes, in the same folder, for unit U0's review.

## Behavior, overall

The owner chose how agent behavior is proven: the next real skill change, run through the new lifecycle (Project 3's settled proof decision). Until that change runs, *agents follow the new lifecycle* is unverified and is reported that way. Static checks, source walks and reviews show the files hold the obligations; they don't show agents act on them.

## What runs, and where

- Static checks, source walks and tests run locally in the Project 1 worktree; no CI.
- Reviews: this design set first, at today's spec stage, then an implementation review after each project unit (U0, U2a, U2b, U2c), before the next unit starts, by Sol xhigh reviewers with no authoring history, started as Router sessions that use Router's scratch folders, as the owner allowed. Each reviewer reads `skill-review` from a detached checkout of the base commit.
