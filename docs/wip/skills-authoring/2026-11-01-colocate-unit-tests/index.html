Colocate unit tests

This change puts your test layout into domain-typescript and domain-rust. A unit test sits beside its module. In TypeScript that is report.test.ts. In Rust it is report_test.rs, declared with #[cfg(test)] #[path = "report_test.rs"] mod tests;, your fixed form. The package's tests/ folder holds only integration tests, end-to-end tests and their helpers, in tests/integration/, tests/e2e/ and tests/support/. When a TypeScript repository already does it another way, the agent asks you before adding the test. Rust asks only when the repository's own instructions or checks require another layout. domain-python already agrees, and no other skill restates where tests go. This is revision 2, after design review 1: the proof oracle now passes only a question asked before any write, and the helpers folder is tests/support/.
