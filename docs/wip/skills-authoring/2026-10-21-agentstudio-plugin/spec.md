## Promise and success

This skill helps agents use their own Agent Studio pane for an agent message, notices, decisions and context while respecting the CLI's attachment and authentication boundaries.

Owner ask: "you need to update the agentstudio skill and also make it into a plugin I can put in sunstack marketplace". The Lead accepted the eight-item source gap list and commissioned this bounded update through a reviewed draft PR. Success means a fresh reader can choose a valid pane command, interpret its refusal and choose a safe next command/action, distinguish a line message from permission or status assertions, handle background and stale-token cases correctly, and find the skill through each marketplace's packaging. No installed-client or behavior-improvement claim follows from static validation.

## Surface allocation and authored body

Trigger: the description above. Main path: own-pane targeting, executable check, background guard, friendly verbs with complete examples, byte limits, Agent Line message and app-owned age separated from hook status, automatic safe fallback, response inspection. Depth stays inline by explicit single-file direction: message update/clear, blocking wait, retained answers/bookmark caveat, exact stale variants, ordering-store refusal, credential/binding recovery, notice queue versus unknown delivery. No runtime reference calls. Proof: independent reference-use observations and packaging checks; no authored executable resources or wire/schema changes.

Keep these invariants inline: `pane.current` is focus, `handle: self` is the caller's pane; never borrow identity or bypass background refusal; the Agent Line is the agent's message, hook status is separate, and notice `--kind done` asserts no completion status; inspect an ask's terminal answer before acting; stale ordered payloads are final, and permission comes only from the actual answer within existing provider rules. Use chat when unavailable; do not turn communication failure into task cancellation.

Normal examples cover notify, nonblocking ask, withdraw, answers, line message, title and pane. Explain `line MESSAGE`, app-owned relative age with no expiry/dimming, `line --clear` and `title --reset`. Long explanations go through chat or an appropriate notice. Keep the message within 200 UTF-8 bytes and title within 256 bytes. Hook status and the line's fixed message icon remain the app's presentation; agents do not assert status through the message. Route help locally through `$AGENTSTUDIO_CLI`. Avoid raw protocol mechanics, session election, storage layout or internal PR labels in runtime prose.

Completion means each attempted call is read as its actual outcome, ask/message ids are retained as needed, and any unavailable communication is reported without extending task authority. Do not claim successful delivery or approval from a queued notice, unknown response or exit code alone.

Recovery teaching remains inline under the explicit one-file decision. The adopted removed-options literal leads to `line "Current message"` or `line --clear`, not retired flags or raw IPC. Credential refusal leads to the owner restarting THIS pane's shell, then a read-only `pane` check, then a new intended call only when safe; never blindly replay the refused notice/ask payload. The check does not establish ask binding or permission. `bindingRequired` leads to separately authorized provider setup/restart, then a fresh ask only if still needed. Ordering-store refusal leaves the store intact, asks the owner to restart the app, then permits a fresh intended line; the independent notice path remains available under its real authentication/attribution requirements. A stale ordered payload is final; inspect context with `pane` BEFORE any distinct next intent. Queued/unknown notice outcomes lead to `pane` inspection when reachable and no blind resend. Non-answer asks lead to a fresh explicit decision through chat or a new ask, never approval from transport exit. Background/unavailable-pane cases use chat when no safe reporting command exists. All next calls use the owning pane's environment and helper; no automatic installation, setting change, identity stripping or token copying.
