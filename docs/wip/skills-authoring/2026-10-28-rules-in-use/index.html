Requirements: the owner's need, success definition, evidence and limits. Specification: the behavior that must hold, including warnings, failures and incomplete checks. Skill design: which files and skills change, the security constraints, and the order of work. Skill verification: planned checks that a wrong build fails, and what stays unverified.

Rules in use

This change finishes #171's rules kit so every later PR (pull request) is made and checked with it. The kit is the shared skill standards, their executable checks, and the skills that run those checks.

It changes domain-skill-crafting (the standards root), skill-rules (the checking procedure), and skill-design, skill-creation, skill-review, skill-orchestrator and skill-audit, together with the repository's rule runner.

The design review comes next, then the owner's OK. The verification part describes planned proof, not completed observations.
