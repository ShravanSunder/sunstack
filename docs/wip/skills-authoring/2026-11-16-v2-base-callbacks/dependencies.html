Which way should the plugins depend?

The workflow plugin may depend on sunstack-dev, but sunstack-dev must never name a workflow skill. Today it does so 43 times. PR #229 made this worse: it swapped the dead v1 names for v2 names, so the base now depends on v2 while v2 depends on the base, and the dependency arrow runs both ways.

The fix uses two mechanisms the repo already has. When base work hands off to a design or delivery step, it returns a token, and the Lead turns that token into the next skill through your skill index. When base work delegates to a helper, it uses whatever agent-management practice the host provides, the same way skill-review already does. After that, the base works with any workflow installed, or with none.

The rule, and where it comes from

This repo's AGENTS.md says: "Practices, operations, audits, presentation and tool manuals do not call upward into phases, orchestrators or roles… Upward work returns the token and payload from shared-references/phase-return-tokens.md; the caller selects the next owner." That token file says the same in one line: a skill "returns one token with its payload instead of naming the next skill. The caller resolves the token." In your setup, the Lead resolves tokens through the devfiles skill index, which already maps each token to its v2 skill.

The dependency picture

The base and the workflow depend on each other. The nine calls into v1 already lead nowhere. If you later replace v2 with a v3, every one of the 34 v2 names breaks again, which is exactly what happened when v1 was removed.

The base names no workflow skill. A dashed arrow is a runtime lookup, not a dependency on a named plugin. The only place that names v2 skills is your skill index, and in this repo the AGENTS.md. Both are configuration, not skills.

One choice: where delegation lives

Kinds 1 and 3 have one obvious fix each. Kind 2 has a real choice, because practices-manage-agents is named like a base practice but lives in the workflow plugin, since it carries v2's role list and model catalog.

What

One base reference says: use the host's agent-management practice if there is one. practices-manage-agents stays in v2.

Gain

Smallest change. The same pattern skill-review already proves out. v2 keeps owning roles and models.

Cost

One more hop. An agent might miss the practice, but your skill index's "Delegate…" row points every session at it.

What

A base practices-delegation owns how to brief, launch and check any helper. v2 keeps only its roles and model catalog.

Gain

The cleanest layering, and the brief and handoff work from the roles inventory would land in the base, where every skill can use it.

Cost

A real skill split through skill-authoring, which overlaps with the role rewrite that is coming anyway.

What

All of practices-manage-agents moves into sunstack-dev.

Gain

No lookup needed.

Cost

The base would then own v2's roles and models. The same problem appears again, one level down.

Proposed, not decided. Rework PR #229 with option A, so the base stops naming any workflow skill today.
