Initiatives, deliverables and one plan each: the v2 skill change

This proposal teaches five sunstack-workflow-v2 skills (design-specification, design-program, design-verification, design-review, role-lead) the model the owner settled on 25 November: an initiative orders numbered projects, each project is one four-part design, and each project is cut into deliverables that select its records and add none. It also creates a v2 plan-implementation skill that writes one plan per deliverable, naming each step in the deliverable and explaining the same steps in the plan, and changing both together when it re-plans. The Lead orders work from initiative status and records each build's results and acceptance on the deliverable.

Still open: seven owner questions. The four that change the edits are who writes a deliverable's scope (Q2), whether depth follows the project number (Q1), where a project lives (Q6) and which plan contract applies (Q7); each has options and a recommendation in the skill design. Nothing has been reviewed or evaluated, and no skill file has changed.
