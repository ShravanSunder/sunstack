Initiatives, deliverables and one plan each: the v2 skill change

This proposal teaches five sunstack-workflow-v2 skills (design-specification, design-program, design-verification, design-review, role-lead) the model the owner settled on 25 November: an initiative orders numbered projects, each project is one four-part design, and each project is cut into deliverables that select its records and add none. Each design phase loads the Demistify guide before it writes a record and adds its own records to the deliverables' scope, so the design check's coverage gate stops passing on an empty report (the independent review's blocker). It also creates a v2 plan-implementation skill that writes one plan per deliverable: the deliverable record holds the step names and what it waits on, and the plan explains each step by id without a list of its own. The Lead orders work from initiative status, names the deliverable before any commission, raises owner decisions as choice records, and records each build's results and acceptance on the deliverable.

Revision 2 takes in the Mac Lead's input and the independent skills review. Still open: five owner questions, each with options and a recommendation in the skill design: what work gets when no deliverable covers it (Q8), what "near" means for depth by number (Q1), where initiatives live (Q6), which plan contract applies and whether its dependency line is fixed in sunstack-dev (Q7), and the two checkers (Q5). Nothing has been design-reviewed or evaluated, and no skill file has changed.
