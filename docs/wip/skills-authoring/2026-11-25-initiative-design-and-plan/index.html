Initiatives, deliverables and one plan each: the v2 skill change

This proposal teaches five sunstack-workflow-v2 skills (design-specification, design-program, design-verification, design-review, role-lead) the model the owner settled on 25 November: an initiative orders numbered projects, each project is one four-part design, and each project is cut into deliverables that select its records and add none. Each design phase loads the Demistify guide before it writes a record and adds its own records to the deliverables' scope, so the design check's coverage gate stops passing on an empty report (the independent review's blocker). It also creates a v2 plan-implementation skill that writes one plan per deliverable: the deliverable record holds the step names and what it waits on, and the plan explains each step by id without a list of its own. The Lead creates the initiative from the owner's numbers and words, starts builds from initiative status in number order while later projects are still designed at their depth, names the deliverable before any build commission, raises owner decisions as choice records, and records each build's results and acceptance keyed to the deliverable. Every run waits for Demistify 1.34.0 to be hosted (it is publishing); the plan skill and role-lead read the "Needs a plan" list that Demistify 1.34.1 adds.

Revision 4 closes the open items of the second round of design reviews A and B, after revision 3 corrected the first round; the mapping of each finding sits at the end of the skill design. Still open: four owner questions, each with options and a recommendation: how much of a step the plan fixes and how much the Implementer chooses (Q9), what work gets when no deliverable covers it (Q8), what "near" means for depth by number (Q1), and where initiatives live (Q6). Reviewer B judged the remaining items checkable at their anchors; nothing has been evaluated, and no skill file has changed.
