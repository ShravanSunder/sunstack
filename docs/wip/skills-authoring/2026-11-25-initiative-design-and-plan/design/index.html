The v2 initiative and plan change

In one sentence: agents now carry an initiative from your numbered projects, through one design per project, into deliverables that each get exactly one plan, one build and recorded proof, and they read progress from the records rather than from chat.

Six sunstack-workflow-v2 skills changed to do this. Five were updated (design-specification, design-program, design-verification, design-review, role-lead), and plan-implementation is new. It shipped as version 0.8.0 on 26 Nov, after your four answers. They're installed in Claude and Codex.

An independent review (24 findings down to 0) and one trigger trial back this change. No behaviour eval has run, and it waits for your go-ahead. Agent sessions started before 26 Nov still use the old skills until they restart.

The model in one picture

There are three levels, and each has one job. The initiative holds your project numbers and the decisions several projects share, and it has no design of its own. A project is exactly one design in four parts. A deliverable never adds design: it picks which of its project's rules and checks it builds, and it is what one plan is written for. Proof comes back to the deliverable, so the status reads from there.

Before this change, the design skills wrote one set under docs/specs/ and knew nothing about initiatives or projects. No v2 skill wrote a plan: the Program Design handed "task slices" to an unnamed planner. The Mac Lead wrote a separate design for each deliverable, and a week of their work had no deliverable row.

What happens, start to finish

This is one pass through an initiative, as the skills now run it. Every arrow into Demistify writes or reads typed records. Nothing is a hand-written status.

Two things hold this order. While project 1 is being designed, a higher-numbered project gets only its needs and open questions (your Q1 answer). And no build starts in project 2 while project 1 still has open core work, unless you say otherwise.

Before any build starts

The Mac Lead asked for this check, and it's the one most likely to stop an agent: work that changes the product needs a deliverable before anyone builds it. The skill names the excuse it blocks: "it's a small fix, the row can come later". Design, review and evidence work name the project instead, because those happen before deliverables exist.
