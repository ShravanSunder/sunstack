Design as HTML: the change to the four-document workflow

This change makes every design a set of linked HTML pages: each of the four documents is a page whose text lives in its sections, with Markdown islands (blocks of Markdown text placed inside a page) for snippets and sections, and every fact has one home that other pages link to. It changes nine sunstack-dev skills, one run each, in order: orchestrator-design (with the design-set contract and the deliverable stage), presentation-html (with the page-medium rule and the released Map), spec-design, discuss-pathfinding, program-design, verification-design, spec-program-review, docs-maintain and plan-implementation (with the plan record); sections and stories on design pages wait for a section that doesn't count stories. Still open: three of the owner's answers: how agents read and check a design, and what goes with the standard links on each need, both taken as defaults until he answers; and his confirmation of the success definition in the Requirements. The design passed its independent review; nothing is implemented, and no run starts without his direction.

The four parts, in order

  1. Requirements: what the change is for, in the owner's words, and its success definition.
  2. Specification: what the changed skills must do, and the standards they state.
  3. Skill design: which skill changes where, in which order, and the decisions taken.
  4. Skill verification: how each part will be shown to hold, and what stays unverified.
