Design as HTML: the change to the four-document workflow

This change makes every design a set of linked HTML pages: each of the four documents is a page whose text lives in its sections, with Markdown islands (blocks of Markdown text placed inside a page) for snippets and sections, and every fact has one home that other pages link to. It changes ten parts of the sunstack-dev skills, in order: the design-set contract, the page-medium rule, presentation-html's design pages, the four phases and pathfinding's requirements record, the design review's navigation check, page upkeep and the plan record; the new Demistify parts follow after their release. Still open: two of the owner's answers (how agents read and check a design, and what goes with the standard links on each need), which the drafts take as defaults.

The four parts, in order

  1. Requirements: what the change is for, in the owner's words, and its success definition.
  2. Specification: what the changed skills must do, and the standards they state.
  3. Skill design: which skill changes where, in which order, and the decisions taken.
  4. Skill verification: how each part will be shown to hold, and what stays unverified.
