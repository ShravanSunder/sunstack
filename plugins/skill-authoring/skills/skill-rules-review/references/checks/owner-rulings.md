# Check: Owner Rulings

This check owns whether the rule's cases can test it: every ruling the owner made on a real piece is a case, the rule's questions give each one its ruled answer when read on the state its request carries, and the cases, bars and floors can carry what this stage claims. Examples overlapping cases are `decision-model-review`'s state-and-evidence item; this check reads the rulings' side.

**Inputs:** the source of the owner's rulings for the rule's standard (its requirements, the owner's fixes, the standard's own home); the development case file; the desk-check record; for each owner-ruled development case, its state as `decision-model-review` defines it: its prepared request (`lint cases --set development --prepare`), or the same request saved by a run; the entry's questions, criteria and tree; the recorded bars. Never held-out contents: their count and label origins only, from whoever holds them.

**Return:** a check record, in the review schema's shape.

**Complete when:** every owner ruling in the source was found in the case file or named as missing, and every owner-ruled development case was read on its state against every item below. Without those states the check is `partial`, naming them as the missing input.

| item | fails when | bad control | smallest correction |
| --- | --- | --- | --- |
| every ruling is a case | a ruling on a real piece that touches this standard has no case, or sits in the `reference` or a question's criteria instead | a product-workflow rule whose `reference` holds the owner's twelve rulings, each with its answer, and whose case file has some of them | put each ruling in the case file with `label_from: owner-ruling`; write the reference's examples from the standard |
| ruled answer on the wire | walking the tree on an owner-ruled case's state, by the criteria as written, ends somewhere other than its ruling; or the desk-check record lacks the case, reached its answer from the question text alone, or read anything but the prepared or saved request | a review table mapping "a public tool used as documented" to "the boundary excludes it, so pass", while the five cases' states show sections full of commands and files, which the first question's criteria call product material | return the rule to its design for the meaning (or the evidence, when the decisive content is missing); never relabel the case |
| real skill text | a case is a copied excerpt, an invented skill or a synthetic passage, or its lines don't match the piece the engine judges | a held-out set whose matches came mostly from invented mini-skills written to be judged | replace it with real text at a fixed revision, its lines taken from the piece the engine judges, confirmed on the collection |
| bars of its own | at development or switch-on, a bar has no development case in `set_from`, or is copied from another rule or from a starting setting without being set | ten recorded bars, every `set_from` empty, on a rule proposed for activation | set each bar on this rule's development results and record the cases that set it |
| floors before any nudge | at switch-on, the cases miss a floor: three real mistakes, three good texts (the before and after of a real fix among them), three near misses, every earlier wrong warning as a must-pass, a held-out set never tuned on | a rule switched on with no real before-and-after pair | hold the rule, listing what it lacks |
| held-out untouched | the author or the reviewer read held-out contents, an example was drawn from one, or a held-out result was tuned on | a corrected question reworded until a held-out miss passed | treat the seen cases as regression cases; a fresh held-out claim needs unseen cases |
