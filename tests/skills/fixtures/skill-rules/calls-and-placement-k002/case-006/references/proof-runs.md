## Carrying Out A Run

Plan, prepare, run, read, in that order:

1. Plan. Shape each request and its checks for the skill's type under the root's proof-by-type standards. IF the claim will be an improvement, plan the control the root requires, and run it before the changed revision's runs. IF the runs characterize behavior or evaluate work drafted from user intent, label that purpose in the plan. Choose the repetitions under the root's standards.
2. Prepare. Write each run's request and checks, and place the checks as the root's conditions for a counting run require.
3. Run. Start each run as those conditions allow, with the request written in step 2.
4. Collect. For each run, take what those conditions ask its record to show. A checkout does not decide which skills the agent loads; the loaded copy shows as the `SKILL.md` path the agent read, or as the host's record of the skill it invoked.
5. Read. Judge each check from the record as those conditions require, and record each rationalization the run shows in the root's form.
6. Rerun or report. Rerun each run those conditions send back for a rerun, and return each named proof gap they call for. IF the user defers evaluation, return that deferral as a named proof gap.

Return the current proof and every remaining gap to whoever assesses the change before independent implementation review.

Complete when each run that ran has its record read and its result and evidence returned, the claim is judged against the root's proof standards, and the proof artifacts are sufficient for assessment or the exact missing observation is returned to the implementer.
